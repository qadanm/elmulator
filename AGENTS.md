# Elmulator contribution rules

Elmulator is independent MIT testing infrastructure. Preserve Swift/Python byte-for-byte parity. Establish expected fixture outcomes from cited external references or deliberately specified synthetic facts before decoder changes. Never change bytes to make a consumer pass. No real VINs, Bluetooth identifiers, private app code, or credentials in commits. Use focused branches, coherent commits, pull requests and passing relevant checks. Maintainers have authorized ordinary development pushes/PRs; releases require separate maintainer approval. Never force-push shared history.

For native Swift work, use relevant installed Apple development skills and repository guidance. If the developer has `building-native-ios27-apps` installed, apply its scope/evidence rules; a private local skill is not a package build dependency. Python-only work does not require unrelated Apple UI guidance. Use installed SDK declarations over cached API claims. Baseline commands: `swift test`, `PYTHONPATH=python/src python -m pytest python/tests`, `PYTHONPATH=python/src python conformance/run_conformance.py --swift-bin .build/debug/elmulator-tcp`. Set DEVELOPER_DIR to the intended Xcode when multiple versions are installed. Work in isolated ticket branches and report exact tests and untested radio behavior.
